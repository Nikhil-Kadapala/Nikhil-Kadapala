01 / Thesis

Fern’s own README is the plan.

Their usage instructions, in order: start with AGENTS.md, copy skills, copy campaigns/ only if you run paid ads, use the MDX examples as format references, then grow the seed. For a personal PhD / builder site, that list collapses. Paid campaigns and Fern SEO posts are out. The agent OS and the MDX pipeline are in.

What Fern is actually giving away

A miniature of buildwithfern.com: Tailwind v4 tokens, cn() that does not eat custom type classes, Zod-validated frontmatter so a bad field fails the build, posts at a sacred URL, and skills that encode repeatable jobs. The seed is deliberately missing shadcn, Shiki, and the real post components.

What this repo already is

Next App Router on Vercel, bun, Tailwind v4, shadcn button + sheet, three MDX kinds (writing, research, projects), dark-only Mastra-inspired visual language, a knowledge graph on the home page, sitemap / robots / RSS. Identity and IA are further along than Fern’s seed. The gap is agent authoring rules, schema validation, and metadata hygiene.

Working rule: if a Fern file encodes how agents behave, import it and rewrite the voice and paths. If it encodes how Fern looks or sells, read it, then leave it.

02 / Decide before any copy

Eight questions that unblock import.

These are one-way or expensive to reverse. Answer them in chat before Wave 1. Recommendations are stated so we can disagree, not so they become silent defaults.

D1. What are we adopting? Decide

A) Operating system only (AGENTS.md, skills, Zod MDX, metadata rules). B) OS + token discipline (keep Mastra values, steal Fern’s “no raw hex” enforcement). C) Visual restyle toward Fern (light, green, 64px display).

Recommend B. C fights DESIGN.md and the shipped dark homepage. A leaves the CSS dump in globals.css ungoverned.

D2. Freeze URLs? Decide

Fern treats /post/[slug] as sacred. This site already has /writing, /research, /projects, plus /about and /github, with sitemap and RSS. Fern’s “don’t rename URLs” rule should be applied here, not copied from Fern.

Recommend: keep current paths. Never import /post.

D3. Dark-only, or light + dark? Decide

Fern ships next-themes and a light-first :root with a .dark override. DESIGN.md says dark canvas is the default, not an option. Importing the theme provider without a light palette would be empty complexity.

Recommend: stay dark-only. Skip theme-provider.tsx and next-themes unless you explicitly want a light research paper mode later.

D4. Token source of truth? Internal conflict

DESIGN.md specifies measured Mastra greys, amber #f0a35a, 54px display cap, Commit Mono. app/globals.css currently maps accent to Tailwind orange-400 and uses a large class dump (.hero-lab, .artifact-row, …) instead of utility tokens. AGENTS.md says @theme inline; the file uses @theme.

Recommend: DESIGN.md wins for values. Fern wins for the rule “tokens live once, no escape hatches.” Reconcile CSS as a later targeted edit, not as a Fern paste.

D5. Voice? Decide

Fern: second-person, first-person plural, no em dashes, present indicative, CTA verbs. This site: first-person singular, argumentative, research cadence (“the score is not the work”). README.md is already a long personal bio, not a project README.

Recommend: steal Fern’s structure (principles, anti-patterns, punctuation, “if you can’t write the why, it isn’t ready”) and rewrite every sentence for Nikhil. Keep em dashes if that is your voice; Fern’s ban is house style, not a law.

D6. Next 15 + bun + oxlint, or Fern’s Next 16 + npm + eslint? Decide

Stack drift is real but orthogonal to the template’s value. Fern uses next-mdx-remote 6 and Zod 4; this repo uses next-mdx-remote 5, no Zod, plus unused @mdx-js/loader.

Recommend: stay on bun / oxlint / App Router at repo root (no src/ move). Add Zod. Bump next-mdx-remote only when the MDX wave lands. Do not take Next 16 as part of “adopting the template.”

D7. One writing pipeline with a type field. Settled. Settled

All long-form uses one MDX pipeline and /writing/[slug]. Frontmatter type: case-study, build-log, research, teaching. Folders under content/writing/. Extra fields: series, paper, course. /research stays a publication catalog. /projects stays a shipped-work catalog. Essays do not live in those trees.

Locked: one Zod schema (discriminated union on type), one loader, filtered /writing index. Do not ship three equal MDX route trees.

D8. Discard contradicting WIP. Settled. Settled

The unpublished three-tree MDX rewrite (pages + untyped loader + CSS dump) would be deleted in waves 2–3. It is not on main.

Locked: restore app pages to main. Keep CI, agent skills, shadcn primitives, cn(), Vercel preview config, and seed MDX as inventory. Land each Fern wave as its own PR.

03 / Import waves

Copy few files. Edit all of them.

Each wave is “import the skeleton, then retune.” Later waves should not start until the previous wave’s edits exist, otherwise agents will follow Fern paths that are wrong here.

  1. Agent OS — import first, heaviest rewrite

    Fern says this is the highest-leverage file. They are right. This repo’s AGENTS.md is four stack bullets. Fern’s is authoring rules plus a full writing-style contract.

    • Import structure of Fern AGENTS.md: token rule, cn() rule, metadata + sacred URLs, no surprise deps.
    • Edit all writing style: first person, evals / memory / RAG vocabulary, proof points (CheckThat!, ResAlign, HarnessBox), anti-patterns (“AI-powered”, empty adjectives).
    • Import .claude/skills/write-post/ as the model for a write-writing skill.
    • Edit all skill paths: content/writing/, lib/mdx.ts, no Kapil voice, no Fern customer links, no src/lib/authors.ts (that file is not even in the seed).
    • Keep existing animation / prototype skills. They do not overlap.

  2. MDX pipeline — import the pattern, not the single-blog shape

    This is the first code import. Today lib/mdx.ts casts frontmatter with as. Fern parses with Zod and drops drafts in production. Slug pages here have no generateMetadata.

    • Import Zod + draft flag + fail-the-build parse from src/lib/posts.ts.
    • Edit all generalize to three schemas in lib/content.ts / a new lib/schemas.ts. Map excerpt vs Fern description.
    • Import MDX component registry idea from src/lib/mdx.tsx (Eyebrow, Quote, remark-gfm).
    • Edit restyle those components to amber / mono eyebrows; do not use Fern’s green quote rule.
    • Import generateMetadata + generateStaticParams pattern from post/[slug]/page.tsx onto writing / research / projects slug pages.
    • Keep compileMDX vs Fern’s MDXRemote until you bump next-mdx-remote. Same job, different call.

  3. Token + cn() discipline — steal the mechanism

    Fern’s utils.ts registers text-display … text-p-x-small so tailwind-merge does not treat them as colors. This repo already has a plain cn(). The type scale here is CSS classes and clamps, not Tailwind font-size tokens.

    • Import extendTailwindMerge once you actually have custom text-* size tokens.
    • Edit all do not copy Fern’s 64px display, 20px body, brand green, or --grid-max-w: 86rem. DESIGN.md already chose 54px cap, 14.5px body floor, 1224px wrap.
    • Edit fold the globals class dump toward utilities over time. That is a rewrite, not an import.

  4. Article chrome — import after tokens exist

    • Import .article-prose idea (Fern’s minimal MDX stylesheet).
    • Edit all retarget to .prose already on this site; dark surfaces, amber links, Commit Mono code.
    • Later rehype-pretty-code / dual-theme Shiki only if writing grows real code samples. Fern’s seed does not include it.

  5. Optional skills — retarget or skip

    • Maybe file-bug → visual QA reports during design-review sessions. Retarget testing/ paths; this repo has no that folder.
    • Rewrite heavily write-case-study → write-project (problem → system → result, first person, no customer metrics theater).
    • Skip SEO writer/editor, launch-campaign, employee-profile, campaigns/.
